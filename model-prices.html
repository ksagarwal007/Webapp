How LLM API Pricing Works

Large language model APIs charge by the token, the small chunks of text a model reads and writes. Prices are quoted per million tokens, with one rate for input (everything you send) and a higher rate for output (everything the model writes). A request costs its input tokens times the input rate plus its output tokens times the output rate, divided by a million.

Two models with the same input price can still differ a lot in cost. A model with cheap input but expensive output is a poor fit for chatbots that write long answers, while a classifier that reads a lot and replies with one word cares mostly about the input rate. Context window size matters too, because a model that cannot fit your documents is not cheaper, it is unusable.

Some providers also offer discounts for cached prompts and for batch jobs that can wait hours for the result. Those are not in the table, but the Cost Forecaster models them, and the Token Counter measures how many tokens your own text uses.

Questions

Where do the prices come from?

From the open-source LiteLLM catalog, refreshed daily by an automated job that checks for suspicious changes. They are not verified against provider billing, so confirm on the provider page before relying on a number.

Why are some models missing?

The list covers the main providers and chat models. Cloud-reseller duplicates, embeddings, fine-tunes and deprecated models are left out.

What does a price per million tokens mean?

Providers bill input and output tokens separately, per million. A typical English word is about 1.3 tokens.

Can I reuse this data?

The prices come from an open-source catalog, so you can get them there directly. Please credit the source if you republish them.
