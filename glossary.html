AI Cost and Token Glossary

Short definitions of the terms used across AI Utility Belt. Tap the ? icon next to a label in any tool for the short version.

Agent Step
One round of an AI agent: the model reads its context, decides, calls a tool and reads the result.
An agent works in a loop. Each step sends the growing context to the model, which may call a tool. The tool's result is added to the context and the loop repeats. Because every step re-sends earlier content, agent costs rise faster than the step count.
Batch Discount
A lower price, often about half, for jobs that can wait hours for the result instead of seconds.
Several providers offer batch APIs: you submit many requests together and get results within a window, often up to 24 hours. In exchange the price is typically about 50 percent lower. It suits evaluations, classification and document processing, not live chat.
Cache Hit Rate
The share of repeated input that is actually served from the cache. Higher means bigger savings.
Not every request benefits from a cache. If requests arrive further apart than the cache lifetime, or the repeated part changes, the cache misses and you pay the full price. The hit rate is the fraction that succeed.
Chunk Overlap
The tokens repeated at the end of one chunk and the start of the next, so an idea that straddles a boundary is not cut in half.
Overlap repeats a little text between neighboring chunks. If a key sentence falls on a boundary, overlap makes sure at least one chunk contains it whole. The cost is some duplicated tokens, so a common choice is 10 to 20 percent of the chunk size.
Chunk Size
How many tokens each piece of a split document contains.
Long documents are split into chunks so each piece can be searched, embedded or sent to a model on its own. Smaller chunks are more precise but lose surrounding context. Larger chunks keep context but are less targeted and cost more to send.
Context Growth
How much extra history is added to each request as a conversation or task continues.
Each turn or step adds new tokens to the history that is sent next time. Context growth models that build-up, until the window is full and older content must be dropped, summarized or truncated.
Context Window
The most tokens a model can handle in one request, counting your prompt, the conversation so far and the reply.
The context window is the model's working memory for a single request. Everything you send (system prompt, history, documents, tool results) plus the reply must fit inside it. When a conversation grows past the limit, older content has to be dropped or summarized. A bigger window lets you send more at once, but you pay for every token you send.
Conversation Turn
One user message plus the model's reply. Each turn re-sends the earlier history, so cost per turn rises.
In a chat, the model sees the whole conversation every time. Turn five includes turns one to four, so later turns cost more than early ones. Long chats are why history trimming and summarizing save money.
Embedding
A list of numbers that represents the meaning of a piece of text, used to find similar passages.
Embedding models turn text into vectors so that similar meanings sit close together. Search systems compare the vector of a question to the vectors of chunks to find the best matches.
Fine-Tuning
Training an existing model further on your own examples so it follows a style or task more reliably.
Fine-tuning adjusts a model with examples of the behavior you want. It can shorten prompts and improve consistency, but it costs to train and the tuned model is often priced higher per token than the base model.
Hallucination
When a model states something false with confidence. Checking sources and structured output help catch it.
Models generate plausible text, not verified facts, so they sometimes invent details. Grounding answers in supplied documents, asking for citations and validating structured output all reduce the risk but do not remove it.
Inference
Running a trained model to get an answer. API usage is inference, and that is what you pay for.
Training builds a model. Inference is using it: you send input and the model generates output. API prices are the price of inference, per token.
Input Tokens
Everything you send to the model: instructions, history, documents and your question.
Input tokens include the system prompt, any earlier messages, attached documents, tool definitions and tool results, plus the new question. In a chat, the whole history is sent again with every turn, so input usually grows faster than people expect.
JSON Schema
A description of the shape JSON should have: which fields exist, their types and which are required.
A schema lets you check a model's JSON output automatically: are all the required fields present, are the numbers numbers, are the values from an allowed list. It catches malformed output before it breaks your code.
LLM
Large language model: an AI trained on huge amounts of text to read and write language.
Large language models such as GPT, Claude and Gemini predict text one token at a time. They power chatbots, coding assistants and many document tools. They are priced by the number of tokens processed.
Output Tokens
The tokens the model writes back. They are billed at the output price, which is usually several times the input price.
Output tokens are generated one at a time, which costs providers more compute than reading input, so they are priced higher, commonly three to five times the input rate. Long answers, step-by-step reasoning and verbose formats all add output tokens. Asking for shorter answers is one of the quickest ways to cut a bill.
Price per 1M Tokens
How providers quote prices: dollars for every million tokens. Input and output tokens are priced separately.
API prices are quoted per million tokens, with one rate for input (what you send) and a usually higher rate for output (what the model writes). To estimate a cost, multiply your token count by the rate and divide by a million. For example, 2,000 input tokens at $3 per million cost $0.006.
Prompt Caching
Providers can store the unchanging start of a prompt and charge a much lower price when you reuse it. Cached tokens are usually billed at a fraction of the normal input price.
Many providers let you mark the repeated beginning of a prompt (a long system prompt, a set of documents, tool definitions) so it is processed once and then reused. Reads of cached text are billed at a discount, often around a tenth of the normal input price, while the first write can cost slightly more. Caches expire after a short time, so the saving depends on how often requests arrive.
Provider
The company that hosts the model and sells access to it, such as OpenAI, Anthropic or Google.
The provider runs the model and sets the price. The same open model can be sold by several providers at different prices, which is why this site lists the model together with its provider.
RAG
Retrieval-augmented generation: look up relevant passages first, then give them to the model with the question.
Instead of sending a whole knowledge base, a RAG system splits documents into chunks, finds the few most relevant ones for each question and sends only those. It cuts cost and helps answers stay grounded in your own sources.
Rate Limit
A cap on how many requests or tokens you can send per minute, set by the provider.
Providers limit requests per minute and tokens per minute, and the limits grow with your usage tier. Hitting a limit returns an error, so high-volume jobs need to retry or slow down.
System Prompt
The standing instructions you give a model before the conversation starts. It is re-sent with every request, so its length adds up.
A system prompt sets the role, rules, tone and format for the model. Because the model has no memory between requests, the system prompt is sent every time. A 1,500-token system prompt across a million requests is 1.5 billion input tokens, which is why trimming it and caching it matter.
Temperature
A setting that controls how random the model's word choices are. Low is steadier, high is more varied.
Temperature changes how adventurous the model is when choosing the next token. Near zero it picks the most likely words, which suits extraction and code. Higher values give more varied, creative text.
Template Variable
A placeholder in a reusable prompt, written like {{name}}, that you fill in each time.
Prompt templates keep the fixed instructions and mark the changing details as variables. When you use the template you supply the values, which keeps prompts consistent and saves retyping.
Token
The unit models read and write, roughly three quarters of an English word. Providers bill by the token.
A token is a chunk of text: a whole short word, part of a long word, a number or a punctuation mark. In English, one token averages about four characters or three quarters of a word, so 1,000 tokens is roughly 750 words. Other languages and code often use more tokens for the same meaning.
Tokenizer
The program that splits text into tokens. Each model family has its own, so the same text can have different counts.
A tokenizer converts text to the token IDs a model reads. OpenAI publishes its tokenizers, so counts can be exact. Anthropic and Google do not offer one that runs offline, so tools like this one show an estimate for those models, typically within 10 to 15 percent.
